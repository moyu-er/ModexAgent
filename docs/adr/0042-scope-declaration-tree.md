# Scope Declaration Tree — the Unified Assembly Base

## Context

ADR-0041 delivered the 10-slot component registry and the assembly pipeline, but composition stayed pool-flat: `pool.yml` + `templates/*.yml` form a two-level roster, workspace resources are wired by business-layer Python glue (`bot/workspace/wiring/`, `bot/service/builders.py` construct tools/memory/experience directly, bypassing the registry), and the main/subagent distinction is hard-coded as two spec types plus `main_agent_name`. The design goal: workspace, pool, and agent all become config-declared, plugin-assembled units; business glue is replaced by declarative assembly; expensive infrastructure (MCP connections, inboxes, memory handles) stays shared. Deliberated against the investigated reference harness, which achieves flexibility via per-session plugin composition but couples plugins to lifecycle machinery (Fibers, disposal cascades, standing-mount generations) that our persistent-pool runtime does not need.

## Decision

**Scope is the sole structural primitive; workspace and pool are preset scope kinds, not architecture concepts.** A kind binds fixed runtime machinery (workspace: multi-live registry + state.db layout; pool: bus/inbox/poller communication scope) plus a resource template and inheritance defaults. The kind's data face — resources, nesting, defaults — is configuration; its machinery face is skeleton and is never slot-replaced.

**The declaration is a tree; nothing executes it.** A `ScopeSpec` tree (workspace → pool → nested agents; parent references in a flattened model, nested YAML is sugar) is validated by a pure `ScopeTreeValidator` (acyclic, connected, exactly one root per pool tree, kind hierarchy legal, peer endpoints exist) and compiled by a pure `ScopeCompiler` into per-agent `AssemblySpec`s consumed by the existing ADR-0041 pipeline. modex_graph is untouched: `GraphSpec`, `TopologyValidator`, and `GraphEngine` are deliberately not reused — their semantics are execution semantics (mandatory START/END, cycles allowed, every node must reach END), all wrong for a declaration tree, where leaves are legitimate dead ends and cycles are invalid. Assembly is a pure function `(config, context chain) → agent`; the reference project's lifecycle machinery is unnecessary because our plugins hold no lifecycle.

**One `AgentSpec`; defaults derive from tree position.** `MainAgentSpec`/`SubagentSpec` unify and `main_agent_name` dies — the root is the sole in-degree-0 node. The root derives main-agent defaults (archive/core/experience memory, approval eligibility, `task` tool, eager registration); non-root nodes derive subagent defaults (session-only memory, lazy materialize). Any node with declared children receives the `task` tool; nested declaration (subagent-of-subagent) becomes config instead of a latent capability. A hard validation rule guards the derivation: an agent with declared children whose compiler-derived effective toolset lacks the `task` tool is a startup error — checked against the compiler's derivation output (effective-value validation runs post-derivation; declaration-shape validation runs pre-derivation), so an explicit override or a profile's wholesale list replacement cannot silently orphan the subtree behind an unreachable dispatch tool.

**Two communication relationships, never conflated.** Parent-child dispatch walks tree edges (the session tree stays runtime-emergent: SessionTreeManager records actual dispatches with invocation branching — the design changes assembly, never the runtime record). Peer is root-to-root communication between trees (ADR-0019 semantics preserved; the receiving peer session is a root session, not a generic node link). v1 restricts peer links to the same workspace; the declaration shape carries no workspace hard-coding, so a future cross-workspace bridge is a validation relaxation plus a plugin, not a schema change.

**Profiles resolve by inheritance + deep merge** — framework defaults ← profile ← local declaration; profiles cannot reference profiles; list fields are replaced wholesale (tool supersets keep their dedicated `tool_supplements` mechanism); final-value provenance is inspectable (WebUI shows which layer each effective value came from). The reference project's whole-row replace was rejected: agent config is nested, and replacing a block to change one scalar silently drops siblings.

**Override semantics are four axes under one meta-principle** (deliberated refinement): parameter override (profiles, inheritance + deep merge), implementation replacement at the registry key (cross-source same `(slot, name)` resolves by source priority **user > project > entry_points > bundled** — reversing ADR-0041's first-seen-wins, which let bundled always win and blocked user plugins from overriding framework defaults; overrides are logged and auditable via `registration_source`; same-source and direct-registration duplicates remain hard errors), implementation replacement at the produced-tool name (the ACI pattern: a supplement like `aci` whose product shares the name `edit` with the default tool resolves as a compile-time recorded replacement — per-pool granularity; the current silent last-write-wins on `ToolManager.register` is the converged-away path), and list override (wholesale). Meta-principle: every override is explicit, resolved at compile time, and source-auditable — never a side effect of assembly order.

**Component factories read a typed context chain** — `WorkspaceContext → PoolContext → AgentContext`, frozen typed carriers; a factory's signature declares which layers it may read, so the type is the capability boundary (the reference's host/agent plane membership is a comment convention; ours is structural). This generalizes the existing `AssemblyContext` and absorbs `SubagentInvocationContext`. Tool configs carry zero path fields — path knowledge lives only in the workspace layer.

**Declaration source of truth is YAML files** (config tree; WebUI writes back via the scope declaration editor). Restart-effective by decision; an `AssemblySpec` hash + pool generation counter is reserved as the seam for future hot reload. Dynamic scope creation (insert node + run the pipeline — isomorphic to subagent materialize) writes config back to files; a generalized spec store is the upgrade path if creation becomes high-frequency.

**Special agents stay code-configured for now** (ExperienceReviewAgent, session compactor): not config-ized in this round; code comments document the extension path — a nested `AgentSpec` riding its host component's config (e.g. the reviewer under `memory_system_config`).

## Considered Options

- **Reuse `GraphSpec`/`TopologyValidator` for the declaration** — rejected: execution vs declaration semantics (above), and it would drag framework config into modex_graph, violating its framework-agnostic boundary.
- **Keep the flat roster, extend fields incrementally** — rejected: cannot express nesting, keeps the Main/Sub type split and the business glue it feeds.
- **Open the skeleton as replaceable slots** — rejected: no second real host shape exists ("one adapter is hypothetical, two make a real seam"). The existing generic `ScopeRegistry[R]` (renamed from `WorkspaceRegistry` by the addressing convergence) + `ResourceFactory` seam is the future entry point if one appears.
- **Literal per-turn agent re-assembly** — rejected in favor of the three-layer lifecycle (process singletons / config-stamped resident cache / per-turn view assembly): approval-resume and turn-tearing costs; the reference project does not rebuild per turn either.
- **Hot reload in v1** — rejected by user decision; seam reserved.

## Consequences

- `main_agent_name`, the Main/Sub spec split, and the same-pool NORMAL-peer concept are removed. Shipped configs use zero same-pool NORMAL peers (verified), so the removal is safe; external-agent pools remain single-node trees with peer links.
- Special-purpose addressing converged onto one scope-path resolution (delivered): `WorkspaceRegistry[R]` is renamed `ScopeRegistry[R]` (same LRU machinery, persistence in `ScopeRegistryStore`), `WorkspacePathResolver` is deleted in favor of `ScopePath` + `resolve_scope_path` (`workspace/scope_path.py`), and `PoolRouter` remains as the session→pool dispatch shell whose agent→pool ownership is a compile-time declaration lookup (`agent_pool_ownership`) — net deletion per the per-wave net-zero-or-negative accounting (each wave shipped a deletion ledger; the context chain was the one sanctioned temporary net-positive, offset by the contract wave).
- The scope-converge SPEC §17 skeleton decisions (persistent pools, shared bus, LRU, InboxPoller) are preserved. N5's session-level config remains deferred (final wave).
- Session-tree machinery is skeleton (always on per pool; only its storage backend is a swappable store), and the session-id format is untouched.
