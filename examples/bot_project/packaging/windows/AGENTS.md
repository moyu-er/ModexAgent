# packaging/windows

Windows installer build for ModexBot. Produces a single `ModexBot-Setup-x.y.z.exe`
(Inno Setup) that bundles a standalone Python runtime, the bot source, the
pre-built React frontend, and a Tauri desktop shell.

## Quick start

```bat
:: From the repo root (full build — frontend + backend + installer):
examples\bot_project\packaging\windows\build.bat

:: Skip frontend rebuild (reuse an existing webui/dist):
examples\bot_project\packaging\windows\build.bat --skip-fe
```

Prerequisites on the build machine:
- Python 3.12 + `uv` (runtime is copied from the active `.venv`)
- Node.js + npm (for `webui/dist`)
- Rust toolchain (`cargo`, `rustc`) — Tauri shell compilation
- Inno Setup 7 (`ISCC.exe` on PATH or at `C:\Program Files\Inno Setup 7\`)

Output: `packaging/windows/ModexBot-Setup-<version>.exe`

## Build pipeline (7 steps)

`build.bat` orchestrates these steps in order. Each step is a standalone
Python script under `packaging/windows/`:

| Step | Script | What it does |
|------|--------|--------------|
| 0 | `sync_versions.py` | Propagate `src/modex_agent/_version.py` → all `package.json` files |
| 1 | `prepare_icon.py` | Convert `webui/public/logo.jpg` → multi-size `logo.ico` |
| 2 | — | Skipped: `uv.exe` no longer bundled (saves ~58 MB) |
| 3 | `build_archive.py` | `git archive` + working-tree overlay → `staging/app/`; prune tests/docs/assets; copy `webui/dist` |
| 4 | `prepare_python.py` | Copy standalone Python 3.12 + `.venv/Lib/site-packages`; strip project code, dev deps, `__pycache__` |
| 5 | `cargo build --release` | Compile Tauri shell → `staging/tauri/ModexBot.exe` |
| 6 | `ISCC modexbot.iss` | Inno Setup compiler → final `.exe` installer |

## Key design decisions

### Port: single source of truth

The WebUI port lives in `config/bot_config.yml` under `webui:`:

```yaml
webui:
  port: 21800
  host: "0.0.0.0"
```

All launch paths (CLI, Tauri shell, launcher, installer shortcuts) read from
this config — no hardcoded port elsewhere. The loader is
`bot/config/webui_config.py`; `MODEXBOT_PORT` env var remains as an escape
hatch (highest priority).

### Tauri shell (replaces Electron)

`src-tauri/` contains the Rust desktop shell:
- `main.rs` — entry point, path resolution, window/tray setup, lifecycle
- `bot.rs` — bot process management (start/stop/monitor), port ownership check
- `monitor.rs` — health polling (every 5s; 3 consecutive failures → quit)
- `tray.rs` — system tray icon + menu
- `window.rs` — window creation, loading page, navigation

The shell reads the port from config via a Python subprocess
(`read_port_from_config`), then probes whether the bot is already running.
If the port is occupied by a **foreign** process (e.g. a dev-env bot on the
same port), it shows a conflict page instead of silently attaching.

Release builds use `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`
to hide the console window. All Python subprocesses use `CREATE_NO_WINDOW`.

### Python runtime

`prepare_python.py` copies the build machine's `.venv` site-packages into the
staging directory, then strips:
- Project code (`modex_agent`, `modex_bot_project` dist-info, editable `.pth`)
- Dev-only deps (`mypy`, `pytest`, `ruff`, `pip`, `coverage`, etc.)
- All `__pycache__` directories

Two `.pth` files (`zz_modex_agent_src.pth`, `zz_modexbot_bot.pth`) are
regenerated by `prepare_python.py` to point at the installed paths
(`{app}/src` and `{app}/examples/bot_project`).

### Source archive

`build_archive.py` uses `git archive` (clean tracked baseline) + working-tree
overlay (uncommitted changes), then prunes non-runtime directories. Two
exclude lists drive pruning:

- Top-level (`_ARCHIVE_EXCLUDES`): `tests/`, `docs/`, `assets/`, `.github/`,
  `rules/`, `scripts/` — repo-wide non-runtime dirs.
- Nested (`_NESTED_EXCLUDES`): `examples/bot_project/tests/`,
  `examples/bot_project/webui/` (pre-built `dist/` is shipped in
  `bot/web/dist/`; Node.js not expected on install target),
  `examples/graph_patterns/` (modex_graph teaching examples, zero bot refs).

The working-tree overlay skips both lists so excluded files are never copied
into staging in the first place.

## Layout

```
packaging/windows/
├── build.bat              # Orchestrator (7-step pipeline)
├── build_archive.py       # Step 3: source archive
├── prepare_python.py      # Step 4: Python runtime
├── prepare_icon.py        # Step 1: icon generation
├── sync_versions.py       # Step 0: version sync
├── fetch_runtime.py       # (legacy) uv.exe fetch — no longer used
├── postinstall.py         # Inno Setup [Run] post-install: CLI shims
├── launcher.pyw           # Standalone launcher (pythonw, no console)
├── modexbot.iss           # Inno Setup script
├── .gitignore             # Excludes staging/, *.exe, logo.ico
└── src-tauri/
    ├── Cargo.toml
    ├── tauri.conf.json
    └── src/
        ├── main.rs        # Entry, path resolution, lifecycle
        ├── bot.rs         # Bot process management
        ├── monitor.rs     # Health polling
        ├── tray.rs        # System tray
        └── window.rs      # Window management
```

## For AI Agents

- The installer size is dominated by the bundled Python runtime and the
  remaining third-party deps. With the legacy LLM SDK (~123 MB of tokenizer
  data) gone, the largest remaining contributors are the office/media skill
  stack (Pillow, lxml, PDF tooling) and cryptography — future optimization
  target.
- `build.bat --skip-fe` reuses the existing `webui/dist` — use it when only
  backend/packaging changes were made.
- After modifying Rust code, step 5 recompiles (~1-2 min). After modifying
  Python/frontend, only steps 3-4-6 rerun (~1 min total).
- The `.gitignore` excludes `staging/`, `ModexBot-Setup-*.exe`, and `logo.ico`
  — these are build artifacts, never committed.
- `fetch_runtime.py` is dead code (uv.exe no longer bundled); retained for
  reference only.
